# Phase 5 organizer guide

This guide applies only after a Phase 5-or-later version is explicitly
deployed and your matching ChatGPT identity has an active assigned-club
membership.

## Your publication scope

You may prepare and preview public details only for an event in an assigned
club that you own or co-organize. Owner and Administrator have
organization-wide access.

Organizer self-publishing is disabled by default. When an Owner or
Administrator explicitly enables it, an eligible assigned Organizer may
publish only events they already own or co-organize. The policy never grants
access to another club or another organizer's event.

## Publication checklist

Preview can be used while public details are still a private draft, including
an honestly undecided location. Before publication, confirm:

1. the event is a confirmed timed or all-day event;
2. summary and public description are complete;
3. attendance is explicitly in-person, online, or hybrid;
4. the corresponding public location or online destination is approved;
5. the event has no unresolved blocking scheduling state;
6. the RSVP mode is honest;
7. any selected public host remains eligible and has canonical consent.

`Location undecided` is useful while drafting, but blocks publication.
Website fields never reveal the private venue, private meeting link, internal
notes, or conflict reasons.

For Meetup, use only the exact individual event page. A confirmed URL is
canonicalized and tracking fragments are removed. Changing it clears the old
confirmation and returns RSVP display to the honest coming-soon state until
the new event URL is explicitly confirmed.

## Preview and publish

Protected Preview uses the public renderer without making a public page. It is
private, no-store, noindex, and scoped to your current event authorization.

Every publish or scheduling action runs a fresh D1 readiness, version, and
conflict check. A preview or readiness checklist is advisory; it does not
reserve authorization. A stale or conflict response preserves the submitted
form data so you can refresh and coordinate.

Scheduled publication is request-driven. The first relevant request at or
after the chosen time attempts the exact version-bound job. It is not a
realtime or exact-to-the-second background scheduler.

## Public lifecycle

- Published confirmed events appear in Upcoming.
- Published completed events may appear in Past.
- Published cancelled events keep a cancellation page but leave Upcoming.
- Scheduled, private, unpublished, archived, deleted, Idea, Draft, and Hold
  records never appear publicly.
- Unpublish removes the public page without releasing a confirmed private
  reservation.
- Restore never republishes automatically.

Website publishing never writes to Meetup. In-app notifications are private
and no email is sent.
